# GDS for AI 2.0 · Eva 桌面端设计规范

这是一套从 Figma 文件《Eva同学新设计0903》的 6 个 1200 × 800 画板反向归纳出的设计契约。目标不是只记录几个颜色值，而是让人和大模型都能稳定复现同一种产品气质、骨架、组件、状态和素材使用方式。

## 适用范围

- 适用：Eva 桌面端首页、输入、技能选择、运营浮层、生成过程、结果编辑六类状态。
- 不适用：移动端、网页营销页、旧版“小智”界面，或未经验证的响应式布局。
- 2.0 以本次新 Figma 为唯一视觉真相；不要混入 `gdsforai-1.0` 的 1440 × 900、旧侧栏或旧分栏尺寸。

## 文件导航

| 文件 | 用途 | 建议读取顺序 |

| `design.md` | 人与模型共同遵守的主规范，包含布局、组件、状态和生成协议 | 1 |

| `references/industry.md` | 行业规范来源与本包采用的决策 | 查证时 |

## 给大模型的最短使用方式

1. 先读取 `design.md`，确认要生成的页面状态。
2. 读取 `tokens.dtcg.json`、`tokens.json` 和 `components.json`，禁止自行近似颜色、尺寸和圆角。
3. 只装配该状态需要的组件；生成中页面不得提前显示完成态内容。
4. 使用 `assets/reference/` 中同名基准图做 1200 × 800 视觉比对。
5. 运行 `node validate.mjs`，再检查文案溢出、图标风格、键盘焦点和颜色对比度。

可直接追加到模型任务中的约束：

> 严格使用 `gds-for-ai2.0`。先判定页面状态，再按 `design.md` 的骨架和 `components.json` 的组件契约搭建；所有视觉值只能来自令牌。以 1200 × 800 基准画板验收，不要按比例缩放，不要混入 1.0 规范，不要使用 emoji 代替图标。未观察到的交互只能采用标为 `[R]` 的建议，并在交付说明中披露。

## 证据等级

- `[O] Observed`：直接从六个 Figma 画板或节点属性读取。
- `[D] Derived`：由多个观测值归纳出的重复规律。
- `[R] Recommended`：为无障碍、交互完整性或工程落地补充的行业建议，不伪装成原稿事实。
